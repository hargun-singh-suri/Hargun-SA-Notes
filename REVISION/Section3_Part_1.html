API Best Practices & Patterns

Complete Encapsulation
Hide internal design entirely. Ex: client never knows if data comes from SQL or a cache
Easy to Use
Clear naming and simple inputs/outputs, so client engineers rarely need to ask questions
Idempotent Operations
Calling it once or 5 times gives the same result. Ex: "set balance to $100" is safe to retry
Pagination
Return large results in pages, not all at once. Ex: fetch 20 comments per request, not 2 million
Asynchronous Operations
For slow tasks, respond immediately with a status and let the client check back later
Versioning
Let old clients keep working when the API changes. Ex: /v1/orders vs /v2/orders

RPC (Remote Procedure Call)

  • RPC lets a client call a function on another machine as if it were a normal local function call
  • But it isn't free — calling across a network is fundamentally different from calling code in the same process
Local Method Call
  • Runs in the same process/machine
  • Extremely fast (nanoseconds)
  • Almost never fails on its own
RPC Call
  • Travels over the network to another machine
  • Slower — network round-trip adds real delay
  • Less reliable — network can drop, time out, or fail
